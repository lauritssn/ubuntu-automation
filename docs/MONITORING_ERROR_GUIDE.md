# Ubuntu Automation - Monitoring Error Guide

This guide explains how to view and troubleshoot monitoring errors generated by the Ubuntu Automation scripts.

## Common Error Examples

- ⚠️ **WARNING: Elevated Error Rate** - 11-20 errors in last 24 hours
- 🚨 **CRITICAL: High Error Rate** - 20+ errors in last 24 hours
- ⚠️ **System Health Check completed** - Issues detected
- 💽 **Disk Space Monitor** - Low disk space warnings
- 💾 **Swap Usage Monitor** - High swap usage alerts

## Overview

The Ubuntu Automation project includes comprehensive monitoring that generates alerts via:

- **Slack notifications** (if configured)
- **System logs** (journalctl)
- **Local log files** (in `/srv/apps/logs/`)

## Types of Monitoring Errors

### 1. System Health Check Errors

The `system_health_check.sh` script monitors various system metrics and generates warnings/errors for:

- **High Load Average** (>80% or >150% of CPU cores)
- **High Memory Usage** (>80% or >95%)
- **High Disk Usage** (>80% or >95%)
- **Service Failures** (critical services not running)
- **Failed Systemd Units**
- **Security Events** (excessive fail2ban actions)
- **Network Connectivity Issues**
- **Elevated Error Rates** (>10 or >20 system errors in 24 hours)

### 2. Error Rate Categories

- **Elevated Error Rate**: 11-20 system errors in 24 hours (WARNING)
- **High Error Rate**: 20+ system errors in 24 hours (CRITICAL)

### 3. System Resource Thresholds

- **Load Average**: Warning at 80% of CPU cores, Critical at 150% of CPU cores
- **Memory Usage**: Warning at 80%, Critical at 95%
- **Disk Usage**: Warning at 80%, Critical at 95%
- **Swap Usage**: Warning at 25%, Critical at 50%
- **Fail2ban Actions**: Warning at 10+ actions in 24h, Critical at 50+ actions in 24h

## How to View Monitoring Errors

### 1. View System Health Check Results

```bash
# View the most recent system health check
journalctl -u system-health-check.service --no-pager -n 50

# View system health check for the last 24 hours
journalctl -u system-health-check.service --since "24 hours ago" --no-pager

# View only warnings and errors from system health checks
journalctl -u system-health-check.service -p warning --no-pager
```

### 2. Check Current System Errors

```bash
# View system errors from the last 24 hours (same check as monitoring script)
journalctl -p err --since "24 hours ago" --no-pager

# Count errors in last 24 hours
journalctl -p err --since "24 hours ago" --no-pager -q | wc -l

# View most recent 10 errors
journalctl -p err --since "24 hours ago" --no-pager -n 10
```

### 3. View Installation and Script Logs

```bash
# Use the built-in log viewer utility
/srv/apps/scripts/utils/system/view_install_log.sh --errors

# View logs in the dedicated log directory
ls -la /srv/apps/logs/

# View specific monitoring script logs
tail -f /srv/apps/logs/system_health_check_*.log
tail -f /srv/apps/logs/lightweight_monitoring_install*.log
tail -f /srv/apps/logs/systemd_timers_install*.log

# View real-time monitoring activity
journalctl -f -u system-health-check.service
journalctl -f -u disk-space-monitor.service
journalctl -f -u swap-monitor.service
```

### 4. Use Monitoring Utilities

The project includes several monitoring utilities in the ubuntu-automation `/utils/monitoring/` directory:


## Troubleshooting Specific Errors

### Elevated Error Rate (11 errors in 24 hours)

1. **Identify Error Sources**:

   ```bash
   # View detailed error breakdown
   journalctl -p err --since "24 hours ago" --no-pager | head -20

   # Group errors by service
   journalctl -p err --since "24 hours ago" --no-pager | grep -oE '_[A-Z]+\[[0-9]+\]' | sort | uniq -c | sort -nr
   ```

2. **Common Error Categories**:
   - **Service failures**: Check with `systemctl --failed`
   - **Disk space issues**: Check with `df -h`
   - **Memory issues**: Check with `free -h`
   - **Network issues**: Check with `ping 8.8.8.8`

### Network Connectivity Issues

1. **External Connectivity Test**:

   ```bash
   # Test external DNS connectivity (used by system health check)
   ping -c 3 8.8.8.8
   
   # Test DNS resolution
   nslookup google.com
   
   # Check network interface status
   ip addr show
   
   # Review network configuration
   systemctl status systemd-networkd
   systemctl status systemd-resolved
   ```

2. **Common Network Issues**:
   - **DNS Resolution**: Check `/etc/resolv.conf` and systemd-resolved status
   - **Firewall Rules**: Verify UFW status with `ufw status verbose`
   - **Interface Configuration**: Check network interface status
   - **Routing**: Review routing table with `ip route show`

### System Health Check Issues

1. **Review Last Health Check**:

   ```bash
   # View the complete last health check
   journalctl -u system-health-check.service --no-pager -n 100
   ```

2. **Check Specific Metrics**:

   ```bash
   # Current system load
   uptime

   # Memory usage
   free -h

   # Disk usage
   df -h

   # Failed services
   systemctl --failed
   ```

## Automated Monitoring Schedule

The monitoring runs on these schedules (configured via systemd timers):

- **System Health Check**: Every hour (hourly)
- **Disk Space Check**: Every 5 minutes
- **Swap Usage Check**: Every hour
- **ClamAV Scans**: Weekly on Sunday at 2:00 AM
- **ClamAV Updates**: Daily at 3:30 AM
- **RKHunter Scans**: Daily
- **RKHunter Updates**: Weekly on Sunday at 1:00 AM
- **Maldet Scans**: Weekly on Wednesday at 3:00 AM
- **Maldet Updates**: Daily at 2:30 AM

### View Timer Status

```bash
# Check all active timers
systemctl list-timers

# Check specific monitoring timers
systemctl list-timers | grep -E "(health|scan|monitor|clamav|rkhunter|maldet|disk|swap)"

# View specific timer details
systemctl status system-health-check.timer
systemctl status disk-space-monitor.timer
systemctl status swap-monitor.timer
systemctl status clamav-scan.timer
systemctl status rkhunter-scan.timer
systemctl status maldet-scan.timer
```

## Log File Locations

### System Logs

- **journalctl**: Main system logging (accessible via `journalctl` commands)
- **Installation logs**: Tagged with `ubuntu-automation-<timestamp>`

### Script Logs

- **Main directory**: `/srv/apps/logs/`
- **System health**: `/srv/apps/logs/system_health_check_*.log`
- **Security scans**: `/srv/apps/logs/clamav_*.log`, `/srv/apps/logs/rkhunter_*.log`
- **Installation logs**: `/srv/apps/logs/<script_name>_*.log`

### View Log Files

```bash
# List all log files
ls -la /srv/apps/logs/

# View recent system health logs
tail -f /srv/apps/logs/system_health_check_*.log

# View recent disk space monitoring logs
tail -f /srv/apps/logs/check_disk_space*.log

# View recent swap monitoring logs
tail -f /srv/apps/logs/check_swap_usage*.log

# Search for errors in all logs
grep -r "ERROR\|CRITICAL\|FAILED" /srv/apps/logs/

# View security scan logs
ls -la /srv/apps/logs/*scan*.log
ls -la /srv/apps/logs/*update*.log
```

## Installed Monitoring Scripts

The following monitoring scripts are installed with Slack notification support:

### Core System Monitoring Scripts

- **`/srv/apps/scripts/system_health_check.sh`** - Comprehensive system health monitoring including:
  - Load average and CPU usage
  - Memory usage monitoring
  - Disk space checks for critical filesystems
  - Service status verification
  - Failed systemd units detection
  - Security monitoring (fail2ban actions)
  - Network connectivity tests
  - Recent system error analysis

- **`/srv/apps/scripts/check_disk_space.sh`** - Disk space monitoring with:
  - Customizable warning and critical thresholds
  - Support for specific disk monitoring via `-d` parameter
  - Daily notification limiting to reduce spam
  - Integration with external monitoring systems

- **`/srv/apps/scripts/check_swap_usage.sh`** - Swap usage and memory pressure monitoring:
  - Configurable swap usage thresholds (25% warning, 50% critical)
  - Memory context analysis
  - Process memory consumption reporting

### Security Scanning Scripts

- **`/usr/local/bin/clamav-scan.sh`** - ClamAV antivirus scanning:
  - Weekly full system scans
  - Malware detection and quarantine
  - Integration with systemd timers

- **`/usr/local/bin/clamav-update.sh`** - ClamAV signature database updates:
  - Daily signature updates
  - Database consistency verification

- **`/usr/local/bin/rkhunter-scan.sh`** - RKHunter rootkit detection:
  - Daily security scans for rootkits and backdoors
  - System file integrity checking
  - Suspicious activity detection

- **`/usr/local/bin/rkhunter-update.sh`** - RKHunter database updates:
  - Weekly database updates
  - Security signature maintenance

- **`/usr/local/bin/maldet-scan.sh`** - Linux Malware Detect scanning:
  - Weekly malware scans focusing on web directories
  - Independent scanning without ClamAV integration
  - Targeted scanning of common attack vectors

- **`/usr/local/bin/maldet-update.sh`** - Maldet signature updates:
  - Daily signature database updates
  - Maintains current threat detection capabilities

### Manual Testing and Utilities

- **`/srv/apps/scripts/utils/monitoring/test_services.sh`** - Comprehensive service testing:
  - Manual execution of all monitoring services
  - Detailed logging and result tracking
  - Independent of systemd timers for troubleshooting

All monitoring scripts support:

- ✅ Slack webhook notifications (when configured)
- 📊 Detailed logging to `/srv/apps/logs/`
- 🔄 Integration with systemd timers for automation
- ⚙️ Configurable thresholds and parameters

## Slack Notifications (if configured)

If Slack webhook is configured, notifications are sent for:

- **System Health Check start/completion**
- **WARNING level**: Elevated error rates, high resource usage
- **CRITICAL level**: Service failures, network issues, excessive errors

The notifications include:

- 🔍 Start notifications
- ✅ Success notifications
- ⚠️ Warning notifications
- 🚨 Critical error notifications

## Best Practices

1. **Regular Monitoring**: Check system health at least daily
2. **Log Rotation**: Logs are automatically rotated, but monitor disk space
3. **Alert Thresholds**: Customize alert thresholds based on your system's normal behavior
4. **Documentation**: Keep track of recurring issues and their solutions
