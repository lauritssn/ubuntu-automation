# Ubuntu Automation - Monitoring Error Guide

This guide explains how to view and troubleshoot monitoring errors generated by the Ubuntu Automation scripts, including the specific errors you mentioned:

- ⚠️ **WARNING: Elevated Error Rate** - 11 errors in last 24 hours
- ⚠️ **System Health Check completed** - 1 issues detected

## Overview

The Ubuntu Automation project includes comprehensive monitoring that generates alerts via:

- **Slack notifications** (if configured)
- **System logs** (journalctl)
- **Local log files** (in `/srv/apps/logs/`)

## Types of Monitoring Errors

### 1. System Health Check Errors

The `system_health_check.sh` script monitors various system metrics and generates warnings/errors for:

- **High Load Average** (>80% or >150% of CPU cores)
- **High Memory Usage** (>80% or >95%)
- **High Disk Usage** (>80% or >95%)
- **Service Failures** (critical services not running)
- **Failed Systemd Units**
- **Security Events** (excessive fail2ban actions)
- **Network Connectivity Issues**
- **Elevated Error Rates** (>10 or >20 system errors in 24 hours)

### 2. Error Rate Categories

- **Elevated Error Rate**: 11-20 system errors in 24 hours (WARNING)
- **High Error Rate**: 20+ system errors in 24 hours (CRITICAL)

## How to View Monitoring Errors

### 1. View System Health Check Results

```bash
# View the most recent system health check
journalctl -u system-health-check.service --no-pager -n 50

# View system health check for the last 24 hours
journalctl -u system-health-check.service --since "24 hours ago" --no-pager

# View only warnings and errors from system health checks
journalctl -u system-health-check.service -p warning --no-pager
```

### 2. Check Current System Errors

```bash
# View system errors from the last 24 hours (same check as monitoring script)
journalctl -p err --since "24 hours ago" --no-pager

# Count errors in last 24 hours
journalctl -p err --since "24 hours ago" --no-pager -q | wc -l

# View most recent 10 errors
journalctl -p err --since "24 hours ago" --no-pager -n 10
```

### 3. View Installation and Script Logs

```bash
# Use the built-in log viewer utility
/srv/apps/scripts/utils/system/view_install_log.sh --errors

# View logs in the dedicated log directory
ls -la /srv/apps/logs/

# View specific script logs
tail -f /srv/apps/logs/system_health_check_*.log
```

### 4. Use Monitoring Utilities

The project includes several monitoring utilities in `/srv/apps/scripts/utils/monitoring/`:

```bash
# View comprehensive system status
/srv/apps/scripts/utils/monitoring/test_services.sh

# Check fail2ban status and security events
/srv/apps/scripts/utils/monitoring/show_fail2ban_status.sh

# View SSH security status
/srv/apps/scripts/utils/monitoring/show_ssh_security.sh

# Check recent SSH attacks
/srv/apps/scripts/utils/monitoring/show_ssh_attacks.sh

# View network security status
/srv/apps/scripts/utils/monitoring/show_network_security.sh

# Check locked accounts
/srv/apps/scripts/utils/monitoring/show_locked_accounts.sh

# View sudo usage
/srv/apps/scripts/utils/monitoring/show_sudo_usage.sh
```

## Troubleshooting Specific Errors

### Elevated Error Rate (11 errors in 24 hours)

1. **Identify Error Sources**:

   ```bash
   # View detailed error breakdown
   journalctl -p err --since "24 hours ago" --no-pager | head -20

   # Group errors by service
   journalctl -p err --since "24 hours ago" --no-pager | grep -oE '_[A-Z]+\[[0-9]+\]' | sort | uniq -c | sort -nr
   ```

2. **Common Error Categories**:
   - **Service failures**: Check with `systemctl --failed`
   - **Disk space issues**: Check with `df -h`
   - **Memory issues**: Check with `free -h`
   - **Network issues**: Check with `ping 8.8.8.8`

### System Health Check Issues

1. **Review Last Health Check**:

   ```bash
   # View the complete last health check
   journalctl -u system-health-check.service --no-pager -n 100
   ```

2. **Check Specific Metrics**:

   ```bash
   # Current system load
   uptime

   # Memory usage
   free -h

   # Disk usage
   df -h

   # Failed services
   systemctl --failed
   ```

## Automated Monitoring Schedule

The monitoring runs on these schedules (configured via systemd timers):

- **System Health Check**: Every 30 minutes
- **ClamAV Scans**: Daily at 2:00 AM
- **RKHunter Scans**: Daily at 3:00 AM
- **Maldet Scans**: Daily at 4:00 AM
- **Disk Space Check**: Every 15 minutes
- **Swap Usage Check**: Every 15 minutes

### View Timer Status

```bash
# Check all active timers
systemctl list-timers

# Check specific monitoring timers
systemctl list-timers | grep -E "(health|scan|monitor)"

# View specific timer details
systemctl status system-health-check.timer
```

## Log File Locations

### System Logs

- **journalctl**: Main system logging (accessible via `journalctl` commands)
- **Installation logs**: Tagged with `ubuntu-automation-<timestamp>`

### Script Logs

- **Main directory**: `/srv/apps/logs/`
- **System health**: `/srv/apps/logs/system_health_check_*.log`
- **Security scans**: `/srv/apps/logs/clamav_*.log`, `/srv/apps/logs/rkhunter_*.log`
- **Installation logs**: `/srv/apps/logs/<script_name>_*.log`

### View Log Files

```bash
# List all log files
ls -la /srv/apps/logs/

# View recent system health logs
tail -f /srv/apps/logs/system_health_check_*.log

# Search for errors in all logs
grep -r "ERROR\|CRITICAL\|FAILED" /srv/apps/logs/
```

## Slack Notifications (if configured)

If Slack webhook is configured, notifications are sent for:

- **System Health Check start/completion**
- **WARNING level**: Elevated error rates, high resource usage
- **CRITICAL level**: Service failures, network issues, excessive errors

The notifications include:

- 🔍 Start notifications
- ✅ Success notifications
- ⚠️ Warning notifications
- 🚨 Critical error notifications

## Best Practices

1. **Regular Monitoring**: Check system health at least daily
2. **Log Rotation**: Logs are automatically rotated, but monitor disk space
3. **Alert Thresholds**: Customize alert thresholds based on your system's normal behavior
4. **Documentation**: Keep track of recurring issues and their solutions
